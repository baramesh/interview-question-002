# เกณฑ์ยอมรับ

- สมัครด้วยข้อมูลถูกต้องแล้วได้ `201`, มีผู้ใช้ใน `auth_q002.users`, และไม่มีรหัสผ่านดิบในฐานข้อมูล
- สมัครชื่อซ้ำได้ `409`; payload ไม่ถูกต้องได้ `400` แบบ Problem Details
- เข้าสู่ระบบถูกต้องได้ JWT; ข้อมูลผิดได้ `401` ด้วยข้อความกลาง
- `GET /api/auth/me` ไม่มี token หรือ token ผิดได้ `401`; token ถูกต้องได้ชื่อผู้ใช้
- หาก token ที่เก็บไว้ใช้งานไม่ได้ หน้า Welcome ต้องลบ token กลับ Login และแจ้งให้เข้าสู่ระบบใหม่โดยไม่แสดงศัพท์ทางเทคนิค
- ทุกหน้าต้องไม่แสดงรหัสข้อสอบ รหัสหน้าจอ หรือข้อความภายใน เช่น `Interview Question 002`, `IT 02-x`, `Account access` และ `JWT`; รหัสเหล่านี้ใช้ได้เฉพาะในเอกสารและชุดทดสอบ
- หน้า Login ต้องไม่แสดงคำอธิบาย Create account ซ้ำ และหน้า Register ต้องแสดงกฎ Username เฉพาะเมื่อค่าที่กรอกไม่ผ่านการตรวจ
- ที่ viewport desktop การ์ด Login ต้องอยู่กึ่งกลางแนวตั้งของพื้นที่ใต้ส่วนหัว ไม่ใช้ระยะด้านบนแบบตายตัว
- หน้า Welcome แสดง `Welcome User: {username}` โดยใช้ชื่อจาก `/api/auth/me` ไม่ใช่ข้อมูลที่ฝั่งหน้าเว็บเชื่อเอง
- ระบบต้องเริ่มต้นและทำงานได้โดยไม่พึ่ง API ของระบบธุรกิจภายนอก
